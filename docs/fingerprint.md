# Модуль fingerprint: отпечаток TLS-клиента в заголовках

Шлюз считает отпечаток TLS-клиента (JA4 и JA3) и передаёт его апстриму в
заголовках. Отпечаток показывает, чем клиент является на самом деле: браузером,
библиотекой или ботом. Заголовки `User-Agent` и `Sec-CH-UA` клиент подделывает,
набор шифров, расширений и кривых — нет.

## Что появляется в запросе

| Заголовок | Значение |
|---|---|
| `X-JA4` | отпечаток JA4: `t13d1516h2_8daaf6152771_02713d6af862` |
| `X-JA3` | отпечаток JA3 (md5, 32 hex) — для совместимости со старыми фильтрами |
| `X-FP-Source` | `gateway` — кто посчитал отпечаток |

Заголовки от клиента **вырезаются всегда** и подменяются значениями из шлюза:
иначе любой пришлёт свой `X-JA4` и выдаст себя за браузер. Апстрим должен
трактовать отсутствие заголовков как «отпечатка нет» и не считать это признаком
робота: так бывает при HTTP/3 без отпечатка, при keep-alive без рукопожатия и
при выключенном модуле.

## Сборка

```bash
go build -o bin/xgate ./cmd/xgate
bin/xgate build --src . \
  --with code.sarnas.ru/xgate-modules/fingerprint=./modules/fingerprint \
  --output bin/api-gateway-fp
```

Или через Docker:

```bash
docker build --build-arg WITH_FINGERPRINT=true -t api-gateway:fp .
```

Без модуля шлюз не оборачивает слушатель: на горячем пути ноль работы.

## Конфиг

```yaml
plugins:
  fingerprint:
    enabled: "true"        # false — слушатель не оборачивается
    ja4_header: "X-JA4"
    ja3_header: "X-JA3"
    source_header: "X-FP-Source"
```

Секция необязательна: без неё модуль работает с этими же значениями.

## Как считается

**TCP+TLS.** Слушатель отдаёт соединение сразу, без чтения. Разбор ClientHello
происходит при первом `Read` — в горутине соединения, поэтому цикл приёма не
блокируется (важно: чтение в `Accept` давало −25% RPS и открывало slowloris).
Отпечаток считается один раз на соединение и живёт в контексте: на запросе
остаются только записи в карту заголовков.

**HTTP/3.** TLS-записей в QUIC нет: ClientHello едет в CRYPTO-фреймах внутри
Initial-пакета. Обёртка UDP снимает header protection, выводит ключи Initial из
DCID, расшифровывает payload и собирает ClientHello (он может занимать два
пакета). Пакет уходит в quic-go байт в байт — разбор идёт на копии. Ключи
кешируются по DCID, иначе на каждый пакет приходится HKDF с четырьмя
расширениями.

**JA4.** Списки шифров и расширений сортируются, GREASE вырезается, в отпечаток
входит ALPN и признак наличия SNI. Формат: `t13d1516h2_<12 hex>_<12 hex>`.

## Стоимость

Замеры на i5-1235U, `go test -bench .`:

| Что | Время | Аллокации |
|---|---|---|
| запрос без отпечатка (только снятие заголовков) | ~12 нс | 0 |
| запрос с отпечатком | ~93 нс | 0 |
| разбор одного QUIC Initial (RFC 9001, A.2) | ~5 мкс | 28 |

Разбор идёт на соединение, не на запрос; рукопожатие TLS стоит ~1 мс.

Нагрузочный стенд `tools/fplab` (два сервера, `/plain` и `/fp`) и `tools/h3load`
для HTTP/3: при 200–300 параллельных клиентах разница с выключенным модулем
лежит в пределах 3–5%, то есть в шуме.

## Ограничения

- **Миграция соединения в QUIC.** Отпечаток привязан к адресу; после миграции
  его не будет. Запись живёт минуту и удаляется при чтении.
- **0-RTT и Retry.** Соединения с ними могут остаться без отпечатка.
- **HTTP/3 под нагрузкой** мерился только на локальном стенде.
- **JA4 не сверен с эталонными векторами FoxIO.** Тесты проверяют формат,
  устойчивость к GREASE и то, что отпечаток не зависит от порядка списков, но
  совпадение с публичной таблицей FoxIO не проверялось.
- **Список запрещённых отпечатков ведёт апстрим**, а не шлюз: шлюз только
  сообщает факт, решение принимает сервис.

## Приёмка

```bash
go test ./pkg/tlsfp/ ./modules/fingerprint/
go test -race ./modules/fingerprint/
```

Проверка на живом: запрос через шлюз, затем посмотреть, что апстрим получил
заголовки. В каталоге aicat это `/catalog/healthz` — счётчик `ja4_accepted`.
